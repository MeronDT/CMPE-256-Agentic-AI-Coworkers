## Today's new concepts

- **Prompt caching breakpoints:** Prompt caching stores the reusable prefix state from the model’s initial prefill so later requests can skip recomputing it. Use explicit breakpoints to save the static parts (like tools and instructions) and rely on implicit caching to reuse as the conversation grows, but keep the cached prefix text exactly identical.
- **Progressive disclosure skills:** When an agent has multiple specialized retrieval methods, expose only each skill’s name and short description by default. Load the full skill instructions only when the current task actually calls for that skill.
- **Lens-as-data skill automation:** Convert the Well-Architected lens (best practices) into a structured dataset and wire it into a review “skill” that pulls evidence from the target repo. Use a deterministic report generator with strict input validation, and prove correctness by running the automation on fixture repositories with verifiable expectations.

## 1. Groundhog Day for AI agents: Prompt caching patterns for using OpenAI models on Amazon Bedrock

**Source:** AWS Machine Learning | **Published:** 2026-10-26 | **Read:** 5 min
**URL:** https://aws.amazon.com/blogs/machine-learning/groundhog-day-for-ai-agents-prompt-caching-patterns-for-using-openai-models-on-amazon-bedrock/

AI agents behave like “Groundhog Day” because each turn requires sending the entire conversation history back to the LLM, causing repeated token costs and slower interactions. Prompt caching breaks this cycle by saving the prompt’s reusable prefix state (key-value vectors) during an initial prefill and reusing it when later requests start with the same text. The article explains both implicit and explicit caching strategies, and how to combine them so static content (tools/instructions) is reused while the conversation history grows.

**Key insights**

- Prompt caching works by saving the model’s prefill key-value (KV) state so later requests reuse it instead of recomputing from the start. *("When a model reads a prompt, it first does a write called prefill. During prefill, it processes every input token and builds its key and value vectors (also known as key-value, or KV), which form the model’s working state.")*
- Explicit vs implicit caching: explicit caching lets you mark where the reusable prefix ends (e.g., tools/instructions), while implicit caching lets Bedrock choose what to cache as the conversation grows. *("Prompt caching can be implicit, where Amazon Bedrock selects where the reusable prefix ends, or explicit, where your code marks that endpoint using prompt_cache_breakpoint.")*
- Cache reuse is sensitive to prompt text equality: if instructions/tool lists aren’t serialized exactly the same, caching may not apply. *("Keep in mind that prompt caching works only when you pass exactly the same text. Make sure that the agent’s instructions and tool lists are serialized the same way every time.")*

**Takeaway:** For agent workloads, cache the static “tools + instructions” with explicit breakpoints, then let implicit caching cover the growing conversation—while ensuring the cached prefix text is serialized identically every time.

**Adds to your knowledge:** You can implement prompt caching for LLM-powered agents on Amazon Bedrock by understanding the prefill/KV reuse mechanism and selecting between implicit and explicit breakpoint strategies.

**Helps your career goal:** This improves cost/performance for an agentic backend system you could discuss in a Summer 2027 internship interview, especially when designing cloud/LLM workflows that need responsive multi-turn behavior.

**Where to focus:** Focus on: “How prompt caching works under the hood,” “Implicit or explicit, and why do we need both?,” and “Watch out for:” (especially the exact-text serialization warning).

## 2. Context Engineering (Agent Memory) for AI Agents Starts with Retrieval

**Source:** LangChain | **Published:** 2026-10-23 | **Read:** 5 min
**URL:** https://www.langchain.com/blog/context-engineering-starts-with-retrieval

AI agents must retrieve information because they have a limited context window, and retrieval can fail in inefficient, overstuffed, or irrelevant/stale ways. In LangChain’s Deep Agents harness, small “just-in-time” searches and tooling reduce context waste and errors. A key design idea is to keep the main agent’s context clean by offloading retrieved text and delegating detailed reading to subagents.

**Key insights**

- Use “progressive disclosure” skills so agents only load niche search instructions when a task needs them, saving context. *("The agent only sees each skill's name and a short description until a task calls for it; then it loads the full instructions")*
- Apply the “retrieve, offload, delegate” pattern: have retrieval return file paths, then let subagents read the files and return only key facts. *("have it write each result to a file and return only the paths. This is the first part of a pattern called “retrieve, offload, delegate”")*
- Prevent oversized tool outputs from polluting the model context by offloading results to files and giving only a path plus a short preview. *("the harness saves it to a file under /large_tool_results/ and gives the agent the path plus a short preview")*

**Takeaway:** When building agent retrieval, return lightweight references (paths) from retrieval, offload large outputs to files, and delegate detailed reading to subagents to keep the main agent’s context small and relevant.

**Adds to your knowledge:** Adds concrete retrieval-engineering techniques for agentic context management: progressive disclosure skills, retrieve/offload/delegate, and hard limits via oversized-result offloading.

**Helps your career goal:** Improves your ability to design robust backend/agent systems that manage context efficiently—useful for internship work involving agent workflows, data pipelines, and performance-aware backend architecture.

**Where to focus:** Re-read: “Package your search know-how as a skill”, “Have your retrieval tool return file paths”, and “Let the harness offload oversized results”. Also skim the “Let subagents filter the results” section for how delegation reduces irrelevant context.

## 3. Automating agentic AI Well-Architected reviews with the AWS Agentic AI Lens

**Source:** AWS Architecture | **Published:** 2026-10-28 | **Read:** 5 min
**URL:** https://aws.amazon.com/blogs/architecture/automating-agentic-ai-well-architected-reviews-with-the-aws-agentic-ai-lens/

The article describes how Smarsh automated AWS Well-Architected Agentic AI Lens reviews by packaging the 150 best practices into a structured dataset and driving an automated assessment workflow through a Claude skill. The skill reads evidence directly from a workload’s GitHub repository, then generates a deterministic Excel workbook that includes cited evidence, gaps, and remediation. Smarsh also “tested the tester” by evaluating the skill against synthetic repositories and comparing pass rates with and without the automation.

**Key insights**

- Treat a review lens as structured data (JSON) and enforce “single source of truth” to prevent invented or misnumbered best practices. *("This dataset is the single source of truth, and the skill is instructed never to invent or renumber items.")*
- Generate reports deterministically with input validation so unknown IDs/invalid statuses fail fast instead of silently producing questionable results. *("The generator validates its input, so unknown best-practice IDs or invalid statuses abort the build and hallucinated items cannot silently ship.")*
- Validate agentic review automation by testing it on synthetic fixture repos and scoring it against verifiable expectations (not just checking outputs manually). *("With the skill, runs passed 16 of 16 expectations. Baseline runs without it passed only 8 of 16.")*

**Takeaway:** When automating architecture/compliance assessments, separate “lens data,” “assessment rules,” and a deterministic “report renderer,” then test the automation against fixture repositories with explicit graded expectations.

**Adds to your knowledge:** You now have a concrete pattern for how to operationalize a published architecture lens: extract the lens into a structured dataset, bind it to an evidence-gathering workflow, and produce a validated, auditable workbook output.
