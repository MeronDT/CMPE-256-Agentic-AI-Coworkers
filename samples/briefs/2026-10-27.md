## Today's new concepts

- **Attestation-gated access:** Use the enclave’s attestation document as an access credential, so clients can verify the exact software running before accepting results. Confirm correctness by validating PCR measurements against values derived from reproducible builds, rather than trusting the service operator or network perimeter.
- **Day-2 inference operations:** Treat inference serving like any other critical backend service: define what must work after deployment (changing traffic, failures, updates, and resource contention). Implement controls for multi-tenant quality of service and cache-aware routing so workload bursts don’t degrade latency-sensitive requests and redundant computation is minimized.
- **Agentic retrieval loop:** Agentic retrieval puts a reasoning agent in the loop so it can plan, call the right knowledge base tool, and retrieve multiple times. The agent then composes an answer only after checking whether the retrieved context is sufficient and has grounded, cited sources.

## 1. How Anchorage Digital and Turnkey verify code with AWS Nitro Enclaves

**Source:** AWS Architecture | **Published:** 2026-10-27 | **Read:** 5 min
**URL:** https://aws.amazon.com/blogs/architecture/how-anchorage-digital-and-turnkey-verify-code-with-aws-nitro-enclaves/

This article explains how Anchorage Digital and Turnkey use AWS Nitro Enclaves to verify that code ran correctly when parsing complex cryptocurrency transactions. It positions “verifiable infrastructure” as a cryptographic alternative to relying on contractual trust, network perimeter security, or reputation. The architecture uses attestation documents and ephemeral signatures so a wallet client can confirm the response came from expected software in a genuine enclave. It also describes tooling improvements (awsnitroverifier and visualsign-turnkeyclient) to make Nitro attestation verification safer and easier to implement.

**Key insights**

- A transaction parsing system needs both correctness and integrity guarantees, and Nitro Enclaves are used to provide a cryptographic answer. *("A transaction parser needs two guarantees: - Correctness: The parsing logic is the exact, unmodified code that was audited and approved. - Integrity: The parsed output hasn’t been tampered with between the parser and the wallet.")*
- Nitro enclave responses are verified by combining an enclave-signed response (ephemeral P-256 key) with AWS Nitro attestation, then validating PCR measurements against reproducible-build-derived values. *("The enclave signs the response with an ephemeral P-256 key and requests an AWS Nitro attestation document from the Nitro Hypervisor.")*
- The Go library awsnitroverifier separates malformed-input parsing errors from attestation validation failures, with actionable error messages like PCR mismatch and expired certificate. *("The library’s clear two-tier error handling separates malformed input (err != nil) from validation failures (result.Valid == false).")*

**Takeaway:** When you implement attestation-based verification, structure your code to separately handle “parsing/format errors” versus “cryptographic validation failures,” and provide specific error messages (e.g., PCR mismatch vs expired certificate).

**Adds to your knowledge:** You’ve learned a concrete pattern for “verifiable compute” using Nitro Enclaves: enclave execution plus attestation-gated verification based on PCR measurements tied to reproducible builds.

## 3. Build agentic retrieval on a Managed Amazon Bedrock Knowledge Base with CDK

**Source:** AWS Machine Learning | **Published:** 2026-10-26 | **Read:** 5 min
**URL:** https://aws.amazon.com/blogs/machine-learning/build-agentic-retrieval-on-a-managed-amazon-bedrock-knowledge-base-with-cdk/

This article explains how “agentic retrieval” improves enterprise question answering compared to classic single-shot RAG. Instead of embedding once and retrieving once, a reasoning agent decides whether to retrieve, which knowledge base to consult, and whether to retrieve again before answering. It then shows how to build and deploy an end-to-end system using an AWS CDK application on a Managed Amazon Bedrock Knowledge Base. The post also emphasizes that because an agent can take different paths per question, observability and evaluation must be built in from the start.

**Key insights**

- Classic RAG can fail on multi-corpus questions because it performs only one retrieval, producing fluent but incomplete answers. *("“Classic Retrieval Augmented Generation (RAG) does one retrieval and one generation.”")*
- Agentic retrieval improves grounding by routing across multiple knowledge bases and repeating retrieval until the returned context is sufficient. *("“The agent checks whether the returned context is sufficient. If not, it loops, routing and retrieving again”")*
- Operational observability is essential because an agent-driven retrieval loop can take a different path for every question, making it hard to verify behavior without instrumentation. *("“An agent that reasons and retrieves in a loop takes a different path on every question. By default you can see neither the path it took nor whether the answer it produced was any good.”")*

**Takeaway:** When building retrieval for enterprise use, design for multi-turn retrieval: let an agent decide which knowledge base/tool to call and enable observability so you can see what the loop did and how good the grounded output is.

**Adds to your knowledge:** You learned a concrete definition of enterprise agentic retrieval: a reasoning agent in the loop that supports multi-turn planning, tool-driven retrieval across knowledge bases, and “grounded, cited answers,” which addresses limitations of single retrieval.

**Helps your career goal:** This supports your Summer 2027 internship goals by giving you an architecture pattern for backend/cloud AI systems: agentic retrieval with managed services, plus an observability/evaluation-first approach that’s important in production distributed systems.

**Where to focus:** Read closely the sections: “From RAG to enterprise agentic retrieval,” “Managed compared to do-it-yourself Knowledge Bases,” and “Why observability and evaluation,” plus the “Solution overview” walkthrough steps 1–6.
